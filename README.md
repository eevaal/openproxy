# OpenProxy Core v0.2.0

OpenProxy — локальное privacy-first ядро управления и мониторинга сетевых
соединений на Python 3.12+. Этот релиз предоставляет конфигурацию, CLI и
управляющий HTTP API. Передача трафика через прокси и мониторинг соединений
пока не реализованы. Перехвата HTTPS, MITM и подмены сертификатов нет.

## Установка

Установите Python 3.12+ и [uv](https://docs.astral.sh/uv/getting-started/installation/),
затем из существующего checkout репозитория выполните:

```bash
uv sync
uv run openproxy version
```

Команда `uv sync` также устанавливает инструменты разработки из группы `dev`.
Для установки пакета в отдельное окружение можно использовать `uv pip install .`.

## Использование

```bash
uv run openproxy config validate
uv run openproxy config show
uv run openproxy start
# В другом терминале:
uv run openproxy status
```

Сервер работает в текущем терминале; остановка — Ctrl+C. По умолчанию слушает
только `127.0.0.1:8000`. Автоматическая перезагрузка выключена.

Для собственного файла передавайте `--config` (или `-c`) после команды:

```bash
uv run openproxy config validate --config /absolute/path/settings.yaml
uv run openproxy config show --config /absolute/path/settings.yaml
uv run openproxy start --config /absolute/path/settings.yaml
uv run openproxy status --config /absolute/path/settings.yaml
```

Для разработки:

```bash
uv run openproxy start --config /absolute/path/settings.yaml --reload
```

`--reload` перезапускает приложение при изменении Python-файлов. Изменение YAML
само по себе не вызывает перезапуск. При изменении `host` или `port` остановите
сервер и запустите его заново: адрес привязки принадлежит процессу Uvicorn.

Коды завершения CLI:

- `0`: команда выполнена; для `status` подтвержден работающий OpenProxy;
- `1`: сервер недоступен, ответил другой сервис или запуск завершился ошибкой;
- `2`: ошибка конфигурации или использования CLI.

Повторный `start` для уже работающего OpenProxy сообщает об этом и возвращает `0`.
Если порт занят другим сервисом, запуск завершается с ошибкой привязки Uvicorn.

## Конфигурация

```yaml
server:
  host: 127.0.0.1
  port: 8000
```

Порядок выбора конфигурации:

1. `--config PATH`;
2. переменная окружения `OPENPROXY_CONFIG`;
3. `config.yaml` в текущем каталоге, если он существует;
4. встроенные значения `127.0.0.1:8000`.

Явный путь и путь из окружения обязательны к чтению: отсутствующий файл вызывает
ошибку. Абсолютный путь работает независимо от текущего каталога; относительный
разрешается относительно каталога, из которого вызвана команда. Для дочернего
процесса перезагрузки путь переводится в абсолютный.

Пустой файл, YAML `null`, синтаксически некорректный YAML и корень не в виде
словаря вызывают понятную ошибку. `{}` и `server: {}` используют значения по
умолчанию; пропущенные поля также получают значения по умолчанию.
Неизвестные поля запрещены, чтобы опечатки не игнорировались.

`port` должен быть целым числом от 1 до 65535. Строки вроде `"8000"`, дробные
значения и `true` не преобразуются в целые числа. `host` принимает IPv4, IPv6
или `localhost`, без схемы, пути и порта. Произвольные DNS-имена и IPv6 с zone ID
не поддерживаются. Для `0.0.0.0` и `::` команда `status` обращается к loopback;
для IPv6 URL формируется с квадратными скобками.

`config show` выводит эффективную конфигурацию выбранного файла с заполненными
значениями по умолчанию. Она не запрашивает работающий сервер. Настройки уже
работающего процесса доступны через `GET /api/v1/config`. Они фиксируются на
момент старта приложения и не меняются от редактирования файла.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | `status`, имя приложения и версия |
| GET | `/api/v1/info` | Название, версия, описание и возможности ядра |
| GET | `/api/v1/config` | Разрешённые публичные поля активной конфигурации |
| GET | `/` | Совместимость с исходным discovery endpoint |
| GET | `/docs` | Интерактивная документация FastAPI |

Пример ответа `/health`:

```json
{"status": "healthy", "name": "OpenProxy", "version": "0.2.0"}
```

`status` требует HTTP 200 и корректный контракт `/health`, включая имя OpenProxy
и непустую строку версии. Один лишь HTTP 200 или `{"status": "healthy"}` не
считается работающим OpenProxy. Версия сервера может отличаться от версии CLI.
Это идентификация сервиса, а не криптографическая аутентификация.

Обычный запуск рекомендуется выполнять через CLI, который передаёт Uvicorn
параметры привязки из YAML. Для ASGI-интеграции остаются `openproxy.main:app` и
фабрика `openproxy.main:create_app`. При самостоятельном запуске Uvicorn его
параметры `--host`/`--port` задаются отдельно; YAML их не переопределяет.

## Локальная безопасность

Ядро не отправляет телеметрию и не вызывает сторонние API. HTTP-проверка `status`
не использует `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY` из окружения и не следует
HTTP-перенаправлениям. В логах нет содержимого YAML и значений ошибочных полей.
API и `config show` используют явный список разрешённых полей (`host`, `port`),
чтобы будущие секреты не попали в ответ автоматически.

При выборе интерфейса вне loopback приложение выводит предупреждение. В этом
релизе API не имеет аутентификации: ограничивайте доступ файрволом или защищённым
шлюзом. По умолчанию API доступен только на loopback.

## Разработка и проверки

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check src tests
uv run mypy
```

Тесты работают без интернета и реальных сетевых устройств:

- `tests/test_config.py`: временные YAML, значения по умолчанию, неверные типы,
  диапазон портов, приоритет путей, ошибки чтения и отсутствие секретов в ошибках;
- `tests/test_api.py`: API через `TestClient`, запуск/остановка lifespan,
  независимость экземпляров и предупреждение для внешнего интерфейса;
- `tests/test_cli.py`: команды через `CliRunner`, HTTPX `MockTransport` для
  проверки статуса и подмена запуска Uvicorn для проверки параметров сервера.

`mypy` работает в строгом режиме для `src` и `tests`. Единственная добавленная
зависимость разработки — `types-PyYAML`; новых runtime-зависимостей нет.

## Как читать код

Начните с `core/config.py`: `load_config()` читает YAML через `safe_load`,
проверяет форму документа и передаёт данные Pydantic. Модели `AppConfig` и
`ServerConfig` описывают допустимые значения, запрещают лишние поля и изменение
проверенных объектов. `ConfigError` отделяет ожидаемые ошибки пользователя.

Далее изучите `cli.py`: команды используют один загрузчик. `start` передаёт
проверенный объект фабрике FastAPI и запускает Uvicorn. `status` отдельно
обращается к `/health`; `config` работает локально без HTTP-сервера.

В `main.py` фабрика `create_app()` собирает приложение. `lifespan` помещает
конфигурацию в состояние конкретного приложения на старте и удаляет при
остановке. Затем посмотрите `api/routes.py` и `api/models.py`: маршруты описывают
поведение, Pydantic-модели — проверяемую структуру ответов и схему OpenAPI.

После каждого модуля прочитайте соответствующий тест: это исполняемые примеры
его использования и ожидаемого поведения при ошибках.

Каталоги `proxy/` и `rules/` пока зарезервированы для следующих этапов. Реальный
прокси, сбор сетевых соединений, правила маршрутизации, TLS и аутентификация
управляющего API в Core v0.2.0 не реализованы.
